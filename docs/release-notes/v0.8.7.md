# DSH Desktop v0.8.7

跟随官方最新 harness：`@deepseek-ai/dsh` 0.1.7-alpha.2（本次不升 harness，改的是壳的"形状"）。

**这一版的主题：不再靠"让用户加白名单"来躲杀软误报，而是把容易被误判的形状去掉。**

## 1. 不再随包 `node.exe`：Host 与 pnpm 由应用自己的 Electron 二进制运行

杀软的**行为**启发式（卡巴斯基那条 `PDM:...`）最敏感的形状之一是：
未签名的**解释器镜像**从深层目录被拉起 → 再拉子进程 → 在用户目录里写大量文件。
我们以前正是这个形状：应用 → `resources/runtime/node/node.exe` → 再 spawn 一个 Node 跑 pnpm。

现在改成官方桌面端的做法：**应用自己的 `dsh-desktop.exe` 以 `ELECTRON_RUN_AS_NODE=1` 当 Node 用**，
Host 与 pnpm 都由它运行。顺带：

- **`--expose-internals` 去掉了**（pnpm 的启动参数）。实测 pnpm 11 的 install/add/remove 都不需要它，
  而这个 flag 在行为引擎眼里非常显眼。
- 因此 electron 版本**精确钉在 `44.0.0`**：harness 的 `node-addon-require-builtin` 只认
  Electron `43.0.0 / 44.0.0 / 45.0.0-alpha.6` 的运行时指纹（实测 43.4.0 会直接拒绝启动），
  所以不能再用 `^` 范围。
- `desktop-runtime.json` 如实记录 `electronVersion` + Electron 内置的 `nodeVersion`（真正跑 harness 的解释器），
  `versions.json` 里的构建期工具链 Node 单独标注。
- **安装包少了约 50 MB / 约 500 个文件**（构建期那份便携 Node 现在只当工具链，不进安装包）。
- 顺带按目标架构剔除 node-pty 的 ConPTY 二进制：真机 x64 安装包里那两份 `win10-arm64`
  永远不会被执行，却正是被杀软一起清掉的文件。

## 2. 启动期不再"自己装软件"：体检自动、修复手动

0.8.5/0.8.6 的 profile 依赖修复是在**启动路径上自动跑 `pnpm install`**——这既是行为启发式最敏感的形状，
用户也无从预期。现在：

- 启动只做**只读体检**（清单 / 已装包 / `pnpm-lock.yaml` / `.modules.yaml` 四方对账）；
- 发现不一致时，托盘多一条 **「修复插件环境（缺失 N · 残留 M）…」**；点了才弹确认并执行，
  修完自动重启 Harness；
- `DSH_DESKTOP_PROFILE_REPAIR=force` 保留给开发/CI 自动跑。

## 3. 误报处理文档与失败说明（0.8.6 已做，这里补齐口径）

- 启动时校验关键随包文件、Host 入口缺失时不重启也不进安全模式，而是直接说明"哪个文件缺、
  很可能被安全软件隔离、加白名单后重装"；
- `docs/ANTIVIRUS-FALSE-POSITIVE.md` 增补本版的"结构性减法"清单与自检命令。

> 仍然建议的做法（按性价比）：**给发布签名**（Azure Trusted Signing / SignPath Foundation 对开源项目免费 /
> EV 证书）——签名是唯一能让启发式"停止怀疑"的手段；本版做的是把**能被怀疑的形状**尽可能去掉。
