# DSH Desktop v0.8.6

跟随官方最新 harness：`@deepseek-ai/dsh` 0.1.7-alpha.2（本次不升 harness，只修壳侧与安装体验）。

- 运行时与 0.8.5 同一绑定单元（dsh 0.1.7-alpha.2 + Node v24.15.0 + pnpm 11.7.0 + bridge 0.5.0）
- typecheck + 单测 + `e2e:bridge`（真实 dsh + 官方认证 Web Host + 桥接契约）全绿
- 壳版本 patch+1（v0.8.6）：应用内「检查更新」即可自动下载安装

## 1. 安装向导重做（不再是最朴素的 NSIS 白板）

- **品牌图**：页头 150×57 + 侧栏 164×314（白底 + 黑色鲸鱼 + 发丝线），安装与卸载向导都用
  （`resources/installer/*.bmp`，由 `scripts/make-icons.mjs` 纯 JS 生成，无外部依赖）。
- **补上欢迎页**：electron-builder 的 assisted installer 默认直接进目录选择；现在多一页说明
  「运行时内置、离线可用、无需装 Node.js」。
- **进度条**改 `smooth`（连续），不再是一格格绿色方块。
- **文案**：目录页写明体积（约 600 MB）与「卸载不删数据」；完成页写明首次启动会发生什么；
  卸载确认页明确「只删程序、不删会话/工作区/插件/凭据」。
- 安装/卸载图标、卸载项显示名（`DSH Desktop 0.8.6`）一并补上。

## 2. 「启动失败」页换成可执行的排查页

壳自带的失败页重画：品牌抬头、错误摘要、四条可执行提示（先重启 Harness / 运行时文件缺失 →
多半被安全软件隔离 / 插件问题走安全模式 / 日志目录位置），并给了三个按钮：
**重启 Harness · 打开日志目录 · 打开诊断页（复制诊断信息）**，右下角显示壳与 harness 版本。

## 3. 杀毒软件误报（PDM）——把"看不懂的崩溃循环"变成一句人话

真机事故：卡巴斯基「主动防御」把随包 `dsh-desktop-host/lib/index.js` 判为
`PDM:Trojan.Win32.Generic` 并清除（这是**未签名 Electron + 内嵌 Node 运行时**的行为启发式误报）。
文件被删后应用开始反复 `Cannot find module …`，三次失败进安全模式——**看起来像插件坏了，方向全错**。

0.8.6 的改动：

- 启动期校验关键运行时文件（Node / pnpm / Host 入口 / bridge / harness 包 / Web 前端 dist），
  缺了就直接说明「哪个文件缺、为什么、怎么办」，不再带着残缺的树启动；
- Host 拉起前再查一次 Host 入口：缺失时**不重启、不计入安全模式**，弹出「运行时文件缺失
  （可能被安全软件隔离）」并给出「加白名单后重装」的步骤；
- 新增 `docs/ANTIVIRUS-FALSE-POSITIVE.md`：误报原因、哈希自查命令、加白名单与向厂商报误报的路径，
  以及长期解法（EV 证书签名）。

> 如果你也遇到过文件被隔离：先把 `%LOCALAPPDATA%\Programs\dsh-desktop` 加入杀毒软件白名单，
> 再从隔离区恢复或重装本版本，最后点托盘「重启 Harness」。
